# 실험 정의

## 경계

외부 측정은 POST /api/ai/tasks 직전의 monotonic 시각을 시작으로 한다.
접수 시간, 첫 STATUS, 첫 비어 있지 않은 TOKEN, DONE을 각각 기록한다.
이는 API 클라이언트 수신 시각이며 브라우저 페인트 시간은 아니다.
승인 요청은 자동 승인하지 않고 APPROVAL_REQUIRED로 별도 집계한다.
함수 수준 비교를 수행하면 API·큐·SSE 지연을 포함하지 않는다고 명시한다.
기존 로그로 관찰할 수 없는 LLM/도구 내부 시간은 null로 두고 추정하지 않는다.

## 표본과 공정성

- 기존 문서의 12×3 전체 인수시험은 유지한다. 메인 집중 실험은 별도 이름과 표본 수로 보고한다.
- 메인 집중 실험: 같은 합성 입력·locale·초기 상태에서 버전별 반복, 동시성 1.
- 준비 실행과 측정 실행을 구분한다. 같은 새 대화 상태를 사용하고 모델 설정은 버전 원본을 보존한다.
- 버전·입력·모델 설정·프롬프트 SHA256·데이터 해시·의존성·호스트·시각을 기록한다.
- 원래 버전 간 reasoning/프롬프트 차이는 고도화 묶음의 일부다. 동일 프롬프트를 강제로 덮어쓰지 않는다.
- 순서/부하/외부 모델 변동을 한계로 기록한다. 실험 중 외부 검색 결과는 고정 데이터와 구분한다.
- 기존 목표 20%는 전체 인수시험 목표다. 부분 실험으로 달성을 확정하지 않는다.

## 집계

성공 표본만 p50·nearest-rank p95 = 정렬값[ceil(0.95*n)-1]로 집계한다.
실패·타임아웃·승인 대기는 분모에 포함해 별도 건수를 표시한다. 실패를 0초로 넣지 않는다.
감소 초 = 기준 − 개선, 개선율 = (기준 − 개선)/기준 × 100.
표본이 작으면 p95를 탐색적 결과로 표시한다. 단일 실행으로 성능 향상을 확정하지 않는다.
응답 성공과 내용 품질 통과를 구분하고, 원문·기대 결과를 검토하여 잘못된 답변이 빨라진 경우를 숨기지 않는다.

## 모니터링

독립 Compose로 Prometheus/Grafana/Loki/Alloy를 실행한다.
수집 가능한 기존 컨테이너 stdout와 외부 측정 지표를 연결한다. 없는 앱 metrics endpoint를 있다고 가정하지 않는다.
trace/task ID는 로그/실험 원자료에 두며 Prometheus label에 넣지 않는다.
대화 원문·인증 정보는 일반 로그에 기록하지 않는다. 원자료에는 합성 실험 출력만 보존한다.

## 확정된 메인 집중 실험

개선 직전 agent `179b685`와 개선 후 agent `3a8f4ed`를 비교한다. backend/MCP/DB는 개선 후 버전으로 고정한다.
3개 합성 시나리오(en 주제 첫 시작, zh 방식 미정 확인, ja 조건 검색)를 버전별 10회씩 실행한다.
순서는 before 5회씩 → after 10회씩 → before 5회씩이다. 전환 직후 각 1회는 워밍업으로 제외한다.
초기 after 탐색 실행은 모니터링 이미지 다운로드와 겹쳐 본 실험에서 제외한다. 본 실험 내내 모니터링은 켜 둔다.
각 시나리오 n=10의 p95는 최댓값이므로 탐색적 수치다. 전체 인수시험 목표 달성 판정에 사용하지 않는다.
